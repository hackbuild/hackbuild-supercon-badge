how it works

phones are the controllers, one host page runs the game, and the badge is the slow public screen. everything meets on one relay.

playhostprojectorbadge control

one tap, start to finish

  1. your phone writes its input to in/your-id.
  2. the host page reads it, about 0.4 s later at 100 phones, measured.
  3. the rules update the game and publish what everyone sees, plus a private note for you.
  4. when the badge's screen changes, the host draws it at 960 x 672, signs it and sends it in 16 kb chunks, three at a time.
  5. the badge checks the signature, acks each chunk and draws.

how the badge draws

e-paper moves pigment, so every update takes time. measured on this badge:

change only0.36 s
quick pass1.25 s
clean pass4.3 s
full color32.6 s

live games, ink, gifs and the arcade draw change-only frames with the booster left on: only pixels that change move, so nothing flashes. erased ink leaves a light ghost, so every 40th frame is clean, and a clean pass follows 4 s of quiet.

what the badge listens for

cmd
signed commands with a one time nonce: play, lights, img, reel
chunk
pieces of a screen or reel, acked in order, saved then swapped in
ink
stroke batches, signed and numbered, drawn by the badge itself
fr
arcade frames, signed and numbered, the newest one wins

it answers with its state: app, busy, mode, draw time. user a and user b go back to the host and run the game's two main controls. the led bar counts down each phase.

what keeps it honest

  • the badge key stays in the host's browser. it names the badge's private path and signs every message with hmac-sha256.
  • photos are sealed to the host, credits to the winner's phone: ecdh p-256 and aes-gcm.
  • a credit is 6 random bytes and 6 bytes of hmac. the capsule machine checks it and spends it once.
  • the game room is public by design. text goes through a word filter and photos wait for approval.
